# Poketwo-AI Technical Notes\n\nAn efficient image classifier and runtime pipeline for identifying Pokémon spawns in Discord autocatchers.\n\nThe versioned training and validation image archives are documented in [`datasets.md`](datasets.md).\nFrom-scratch training, fine-tuning, and export instructions are in [`training/MODEL_ARTIFACTS.md`](training/MODEL_ARTIFACTS.md).\n\n## Part 1: Model Card & Development Decisions\n\n### 1. Target Platforms & Resource Constraints\nA key design goal for this model is complete cross-platform portability. The runtime must run seamlessly on:\n*   **Desktop-Compute Environments**: Local Windows/Linux desktop workstations & laptops, as well as remote VPSs and servers.\n*   **Low-Compute Edge Environments**: Android smartphones running inside a **Termux** or similar terminal environment.\n\n#### The Android/Termux Challenge\nIn Termux, native GPU acceleration (such as CUDA or DirectML) is unavailable. There are unfortunately also no available Android binaries for @tensorflow/tfjs-node. The most logical alternative I found is TensorFlow.js. TensorFlow.js is restricted to a pure CPU or WebAssembly (WASM) execution backend. Running a standard, off-the-shelf image classification model (such as ResNet or standard MobileNet) on a mobile CPU results in quite high latency (often 1.5 to 4 seconds per image) and severe RAM bottlenecks.\n\nTo thus achieve sub-100ms inference times on low-power mobile CPUs, the model's footprint, memory consumption, and mathematical operation count had to be minimized from the ground up.\n\n---\n\n### 2. Architectural Tradeoffs & Decisions\n\n```\n[Raw Image]\n   │\n   ▼ (Preprocessed via Sharp: Normalized, Saturation boosted, Stripped Alpha)\n[64x64x3 Tensor]\n   │\n   ▼ (Standard Conv2D: Capture raw color/edge relationships)\n[Initial Feature Maps]\n   │\n   ▼ (3x SeparableConv2D Blocks: High feature depth, low parameter count)\n[Aggregated Vectors]\n   │\n   ▼ (GlobalAveragePooling2D + Dense + Dropout: Classify with low memory footprint)\n[1279 Class Probabilities]\n```\n\n#### Input Dimensionality Selection ($64 \times 64 \times 3$)\nA standard image size of $224 \times 224 \times 3$ yields $150,528$ input features.\nBy reducing the dimensions to $64 \times 64 \times 3$, the input feature space is restricted to $12,288$ variables, **a 91.8% reduction in computational complexity** right at the entry point of the network. Empirical testing showed that at 64px, distinct color patterns, forms, and silhouettes are still preserved well enough to map species boundaries correctly.\n\n#### Computation Minimization via Separable Convolutions\nTo maintain high performance on CPU-bound mobile devices, standard convolutional layers are replaced with **Depthwise Separable Convolutions** (`SeparableConv2D`) after the initial layer.\n\n*   **Standard Conv**: $3 \times 3 \times 32 \times 64 = 18,432$ parameters.\n*   **Separable Conv**: $(3 \times 3 \times 32) + (32 \times 64) = 2,336$ parameters.\n\nBy making this choice, **parameters for this layer are reduced by 87.3%**, leading to a much smaller model binary and a substantial drop in the floating-point operations required per forward pass.\n\n#### Generalization via Label Smoothing\nDiscord spawn images often have low-contrast differences, compression artifacts, or highly similar-looking regional variants (e.g., Alolan vs. Kantonian forms). Under standard categorical crossentropy, models can quickly become overconfident on training data, leading to poor generalization.\n\nThis architecture uses **Label Smoothing (0.1)**. Instead of pushing the target class to $1.0$ and others to $0.0$, the targets are adjusted to $0.9$ for the correct class, distributing the remaining $0.1$ across incorrect classes. This regularizes the network, preventing overconfident output boundaries and improving accuracy on real-world Discord attachments.\n\n---\n\n## Part 2: Model Specifications\n\nThe production model accepts 64x64 RGB images and predicts 1,279 classes. Validation accuracy is 99.451%, with 99.870% top-5 accuracy. The ordered class list is provided in [`model/layers/labels.json`](model/layers/labels.json). Each array index matches the corresponding model output index.\n\nThe network uses localized pooling and global average pooling to transition from spatial data to class predictions. Dynamic Dependency Injection\nTo prevent high startup times and conserve system RAM when the bot process is idle, heavy packages like `@tensorflow/tfjs` and native C++ image processing binders (`sharp`) are lazily loaded only when inference is requested.\n\n```javascript\nasync function loadAiDependencies() {\n  if (!tfLib) {\n    tfLib = require("@tensorflow/tfjs");\n    tfLib.enableProdMode();\n  }\n  if (!sharpLib) {\n    sharpLib = require("sharp");\n  }\n  return { tf: tfLib, sharp: sharpLib };\n}\n```\n\n---\n\n### 2. The SeparableConv2D Serialization Hotfix\nThe standard Keras-to-TF.js converter toolchain serializes weight metadata properties (`kernel_initializer`, `kernel_regularizer`, and `kernel_constraint`) that are invalid or unsupported in the Javascript implementation of `SeparableConv2D` [1.1.1, 1.1.2].\n\nIf left unpatched, the engine throws a critical error and fails to mount the model. Rather than forcing developers to use patched model formats, the codebase intercepts and cleans the model's topology structure directly in memory at runtime:\n\n```javascript\nfunction scrubSeparableConv2D(config) {\n  if (Array.isArray(config)) config.forEach(scrubSeparableConv2D);\n  else if (config && typeof config === "object") {\n    if (config.class_name === "SeparableConv2D" && config.config) {\n      delete config.config.kernel_initializer;\n      delete config.config.kernel_regularizer;\n      delete config.config.kernel_constraint;\n    }\n    Object.values(config).forEach(scrubSeparableConv2D);\n  }\n}\n```\n\n---\n\n### 3. High-Performance Shard Consolidation\nStandard file-system APIs can encounter latency spikes or locking conflicts on low-end servers and Android Termux environments. The execution engine loads individual weight shards asynchronously into raw memory buffers, stitching them together to instantiate the model:\n\n```javascript\nasync function loadLayersModelFromDisk(modelDir) {\n  const { tf } = await loadAiDependencies();\n  const modelJsonPath = path.join(modelDir, "model.json");\n  const modelJson = JSON.parse(await fs.promises.readFile(modelJsonPath, "utf8"));\n\n  scrubSeparableConv2D(modelJson.modelTopology);\n\n  const allWeightSpecs = [];\n  const shardBuffers = [];\n\n  for (const group of modelJson.weightsManifest || []) {\n    if (Array.isArray(group.weights)) {\n      allWeightSpecs.push(...group.weights);\n    }\n    for (const relPath of group.paths || []) {\n      const absPath = path.join(modelDir, relPath);\n      const shard = await fs.promises.readFile(absPath);\n      shardBuffers.push(shard);\n    }\n  }\n\n  const weightDataBuffer = Buffer.concat(shardBuffers);\n  const weightData = weightDataBuffer.buffer.slice(\n    weightDataBuffer.byteOffset,\n    weightDataBuffer.byteOffset + weightDataBuffer.byteLength\n  );\n\n  return tf.loadLayersModel({\n    load: async () => ({\n      modelTopology: modelJson.modelTopology,\n      format: modelJson.format,\n      generatedBy: modelJson.generatedBy,\n      convertedBy: modelJson.convertedBy,\n      weightsManifest: modelJson.weightsManifest,\n      weightSpecs: allWeightSpecs,\n      weightData,\n    }),\n  });\n}\n```\n\n---\n\n### 4. Non-Blocking Preprocessing Pipeline\nRunning typical HTML5 Canvas processes in Node.js requires loading massive emulated canvas dependencies. Instead, the preprocessing pipeline uses `sharp` to scale, color-modulate, and prepare images.\n\n*   **Alpha-Channel Removal**: Spawns can contain varying transparency parameters depending on the source platform. `.removeAlpha()` converts transparency to clear, solid backgrounds.\n*   **Contrast Enhancement**: When matching hard-to-distinguish variants, the pipeline optionally applies `.normalize().modulate({ saturation: 1.2 })` to normalize color contrast and amplify color vibrancy, making subtle feature changes easier for the network to recognize.\n\n```javascript\nasync function preprocessImage(url, optimizeImage = true) {\n  const { tf, sharp } = await loadAiDependencies();\n  const response = await axios({\n    url,\n    responseType: "arraybuffer",\n  });\n\n  let sharpInstance = sharp(Buffer.from(response.data));\n  if (optimizeImage) {\n    sharpInstance = sharpInstance.normalize().modulate({ saturation: 1.2 });\n  }\n\n  const imageBuffer = await sharpInstance\n    .resize(64, 64)\n    .removeAlpha()\n    .raw()\n    .toBuffer();\n\n  return tf.tidy(() => {\n    const tensor = tf.tensor3d(new Uint8Array(imageBuffer), [64, 64, 3], "int32");\n    const normalizedImage = tf.cast(tensor, "float32").div(tf.scalar(255.0));\n    return tf.expandDims(normalizedImage, 0); // [1, 64, 64, 3]\n  });\n}\n```\n\n---\n\n### 5. Leak-Free Prediction Interface\nTo prevent gradual memory bloat, the engine wraps the output prediction logic inside `tf.tidy()` and explicitly disposes of the input image tensor after prediction completes.\n\n```javascript\nasync function predict(url) {\n  const { tf } = await loadAiDependencies();\n  const activeModel = await getModel();\n\n  const startTime = Date.now();\n  const imageTensor = await preprocessImage(url, false);\n\n  const predictedIndex = tf.tidy(() => {\n    const prediction = activeModel.predict(imageTensor);\n    const argMaxTensor = prediction.argMax(1);\n    return argMaxTensor.dataSync()[0];\n  });\n\n  // Explicit garbage collection of input tensor\n  imageTensor.dispose();\n\n  const labels = require("../model/layers/labels.json").classes;\n  const name = labels[predictedIndex];\n\n  return name;\n}\n```\n
